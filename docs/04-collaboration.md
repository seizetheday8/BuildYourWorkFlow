# 04 · 协作规范

> 本项目由 4 个 AI 端协作开发。本文件定义各端角色、信息流向、命名约定与
> 硬规则。任何一端在本仓库内行动前，先读本文件。

---

## 1. 四个端

| 端 | 代号 | 位置 | 核心能力 |
|----|------|------|---------|
| DeepSeek 网页端 | **DS** | 云端 | 架构设计、技术决策、文档主笔 |
| Claude Code + DeepSeek V4 | **CC** | 本地 | 文件操作、git、代码实现、测试执行 |
| ChatGPT 网页端 | **GPT** | 云端 | 红队审阅、挑漏洞、对比方案 |
| VSCode Codex | **CX** | 本地 | 函数级代码补全、测试片段 |

**一句话分工**：
- DS 想，CC 做，GPT 挑刺，CX 补细节。

---

## 2. 三条硬规则

### 规则 1 · 主笔唯一
一份文档同一时间只由一端主笔。其他端只能审阅，不能直接改写。
主笔变更需要 DS 明确宣布。

### 规则 2 · 落盘唯一
**只有 CC 能对本仓库执行写操作**（创建、修改、git commit、git push）。
DS / GPT / CX 的输出必须经过 CC 才能进入仓库。

原因：DS / GPT 是云端对话，无仓库访问权；CX 只做代码片段级补全，
不负责仓库级操作。让 CC 独占写权限，避免多端并发导致冲突。

### 规则 3 · 信息回流
任何一端的输出，必须回流到 DS，由 DS 决定是否采纳、如何修订。
禁止"CC 直接采纳 GPT 意见"或"CC 自己发挥"。

原因：DS 掌握全局架构上下文，是唯一能判断某条意见是否与整体设计
冲突的位置。

---

## 3. 信息流向

标准一轮协作：

    ① DS 提出变更（在主对话中给出完整内容）
         ↓ 用户复制
    ② CC 落盘 + commit + push
         ↓ 用户复制仓库 URL / diff
    ③ GPT 红队审阅（挑毛病、提反对意见）
         ↓ 用户复制审阅意见
    ④ DS 决定采纳 / 否决 / 修改
         ↓ 用户复制下一轮变更
    ⑤ CC 落盘 + commit + push
         ↓
    闭环完成

每一轮只推进一个主题。主题完成后才开下一轮。

## 4. 仓库结构约定

    BuildYourWorkFlow/
    ├── README.md              # 门面，仅在定位变化时改
    ├── roadmap.md             # 里程碑与时间线
    ├── docs/
    │   ├── 00-overview.md     # 方案总览
    │   ├── 01-architecture.md # 架构详解（待建）
    │   ├── 02-token-strategy.md # Token 优化策略（待建）
    │   ├── 03-evaluation.md   # 评测方案（待建）
    │   └── 04-collaboration.md # 本文件
    └── src/                   # 代码（Phase 0 时建）

**docs 编号规则**：
- `00` 保留为总览
- `01-09` 为项目核心文档（架构、策略、评测等）
- `10+` 为专项记录（会议、实验日志等）
- 编号一旦分配不再重排，新增只能往后加

## 5. Commit Message 约定

格式：`<类型>(<范围>): <描述>`

| 类型 | 用途 | 示例 |
|------|------|------|
| `docs` | 文档变更 | `docs: add collaboration rules` |
| `feat` | 新功能 | `feat(telemetry): add token logger` |
| `fix` | 修 bug | `fix(context): handle empty history` |
| `refactor` | 重构 | `refactor(agent): extract llm client` |
| `chore` | 杂项 | `chore: update gitignore` |
| `test` | 测试 | `test(telemetry): add concurrency test` |

**范围可选**，但涉及代码模块时建议带上。

---

## 6. CC 的执行纪律

CC 收到的每条指令应包含：
1. 任务目标
2. 明确的禁止事项
3. 验收标准
4. 汇报格式

CC 在任何步骤失败时**立即停止并汇报**，不尝试替代方案。
禁止 CC 在未获指令时主动修改仓库。
