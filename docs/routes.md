# Routes · 路由规则

> 决定"这个任务该给哪个端"。
> 本文件是**实验版 v0**，跑一周后根据记录迭代。
>
> 关联：[docs/roles/](roles/) 节点能力 · [docs/decisions/](decisions/) 路由决策

---

## 1. 路由原则

**能用网页端就用网页端。必须本机执行才用本地端。**

理由：
- 网页端（ds-web / gpt-web）：免费或订阅内，不产生 API 账单
- 本地端（cc-local / cx-vscode）：按量计费，有真实成本

---

## 2. 路由规则表（v0）

| 任务特征 | 首选 | 备选 | 理由 |
|---------|------|------|------|
| 问答 / 解释概念 / 讨论 | ds-web | gpt-web | 免费 |
| 架构设计 / 方案生成 | ds-web | gpt-web | 免费 + 推理强 |
| 信息检索 / 联网查资料 | gpt-web | ds-web | 检索能力强 |
| 代码审阅 / 文档审阅 | gpt-web | cx-vscode | 沙箱读写 + 独立视角 |
| 读/写/改本机文件 | cc-local | cx-vscode | 只有本地端能碰本机 |
| 跑命令 / 测试 / 构建 | cc-local | cx-vscode | 只有本地端能执行 |
| 跨文件重构 | cc-local | cx-vscode | 需要本机文件系统 |
| 简单代码生成（无文件操作） | ds-web | cc-local | 免费优先 |

**判断流程**：
1. 需要碰本机文件或执行命令？→ 本地端
2. 需要联网检索？→ gpt-web
3. 需要独立审阅？→ gpt-web
4. 其他 → ds-web（默认最便宜）

## 3. 实验记录

> 规则是"实验版"，需要真实数据验证。每次路由后填一行。

| 日期 | 任务 | 按规则给谁 | 实际给谁 | 是否一致 | 结果 | 备注 |
|------|------|-----------|---------|---------|------|------|
| YYYY-MM-DD | ... | ... | ... | 是/否 | 好/中/差 | ... |

**记录规范**：
- "按规则给谁"：查规则表得到的答案
- "实际给谁"：你实际选的端
- "是否一致"：两者是否相同
- "结果"：任务完成质量（好 / 中 / 差）
- "备注"：不一致的原因、或质量差的原因

---

## 4. 判断标准

跑一周后，统计：

| 指标 | 目标 | 含义 |
|------|------|------|
| 一致率 | ≥ 70% | 规则与实际选择的一致性 |
| 不一致中"规则错了"的比例 | ≤ 50% | 如果不一致是因为规则不对，规则需要改 |
| 结果"好"的比例 | ≥ 80% | 路由没有损害任务质量 |

**如果三个指标都达标** → 规则可用，进 Phase 2 实现自动化
**如果一致率低** → 规则太模糊，需要细化
**如果结果差** → 路由牺牲了质量，需要调整（不能为了省钱牺牲任务完成）
