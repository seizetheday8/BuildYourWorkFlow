# Code Harness

> 一个面向研发场景的个人 AI 工作流系统。通过 Supervisor-Worker 多 Agent 协作、上下文分层、语义缓存与 Agent 间通信压缩，在真实编码任务中量化降低 Token 消耗与端到端延迟。

## 为什么做这个

日常用 AI 写代码时遇到三个真实痛点：
- **Token 消耗大**：长任务上下文迅速膨胀，单次对话成本失控。
- **上下文管理混乱**：多轮任务后模型"忘记"关键决策，需要反复人工提示。
- **多步骤任务需手动编排**：拆任务、切模型、传上下文全靠人肉。

本项目以 **Harness 工程**（围绕模型运转的调度、状态、预算、上下文基础设施）为核心，目标是把上述过程自动化并量化收益。

## 核心目标

| 目标 | 指标 |
|------|------|
| Token 节省 | 相比单 Agent 全上下文基线，节省 ≥ 50% |
| 延迟降低 | P95 端到端延迟降低 ≥ 30% |
| 质量保持 | 任务完成率 ≥ 基线的 95% |
| 工程落地 | Go 控制平面 + Python Agent 编排的双语言架构 |

## 架构总览

（架构图见 docs/00-overview.md）

    Go 控制平面  ──gRPC──►  Python Agent 编排层
    ├ 任务路由              ├ Supervisor Agent
    ├ 预算控制              ├ Code / Research / Review Worker
    ├ 状态持久化            ├ 上下文管理层（缓存 / 压缩 / 记忆）
    └ 可观测性              └ Agent 间结构化通信协议
